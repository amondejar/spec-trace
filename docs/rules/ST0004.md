# ST0004: Implemented requirement without tests

| Default severity | Reported on |
| --- | --- |
| Warning | Spec |

## What it means

An active requirement is implemented (according to the `[assembly: SpecTraceImplemented]` attributes of the referenced projects) but no test in this project has `[Verifies]` for it. Only checked in test projects (`IsTestProject=true` or `SpecTraceRole=Tests`).

## Example

```text
## ORD-002: Cancel order   <- implemented in OrderService.Cancel, no tests
```

## How to fix it

Add tests with `[Verifies(Requirements.ORD_002, AcceptanceCriteria.ORD_002.AC_n)]`. Tests marked `Skip` or `[Ignore]` do not count.

## IDE code fix

Refactoring **Generate tests for ORD-002 in <test project>** on the `[Implements]`: creates `Specs/ORD_002_...Tests.cs` with one test per pending criterion.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: several rules are reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0004.severity = error   # or warning, suggestion, none
```
