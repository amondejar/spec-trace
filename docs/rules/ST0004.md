# ST0004: Requisito implementado sin test

| Severidad por defecto | Se reporta en |
| --- | --- |
| Warning | Spec |

## Qué significa

Un requisito activo está implementado (según los `[assembly: SpecTraceImplemented]` de los proyectos referenciados) pero ningún test del proyecto tiene `[Verifies]` para él. Solo se comprueba en proyectos de test (`IsTestProject=true` o `SpecTraceRole=Tests`).

## Ejemplo

```text
## ORD-002: Cancelar pedido   ← implementado en OrderService.Cancel, sin tests
```

## Cómo arreglarlo

Añade tests con `[Verifies(Requirements.ORD_002, AcceptanceCriteria.ORD_002.AC_n)]`. Los tests con `Skip` o `[Ignore]` no cuentan.

## Code fix en el IDE

Refactorización **Generar tests de ORD-002 en <proyecto de tests>** sobre el `[Implements]`: crea `Specs/ORD_002_...Tests.cs` con un test por criterio pendiente.

## Configurar la severidad

En un `.globalconfig` en la raíz del repositorio (no `.editorconfig`: varias reglas se reportan sobre ficheros `.md`):

```ini
is_global = true
dotnet_diagnostic.ST0004.severity = error   # o warning, suggestion, none
```
