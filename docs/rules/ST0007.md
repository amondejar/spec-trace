# ST0007: Duplicate ID in the specs

| Default severity | Reported on |
| --- | --- |
| Error | Spec |

## What it means

A requirement ID appears twice (in the same file or in different files), or an `AC-n` criterion is repeated within a requirement.

## Example

```text
## ORD-001: Create order
...
## ORD-001: Create urgent order   <- duplicate
```

## How to fix it

Renumber one of them. IDs are never reused, even when a requirement is retired: use `Status: deprecated`.

## After merging two branches

The usual cause in a team: two branches proposed "the next ID" of the same spec. Bring the base branch into yours and run:

```bash
dotnet spectrace ids --fix
```

It renumbers only the requirement your branch added, its `spectrace.lock` line and the references in the code and
tests your branch added; the other requirement keeps its ID. Review the result with `git diff`.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: several rules are reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0007.severity = error   # or warning, suggestion, none
```
