# ST0010: El enunciado cambió después de revisarse

| Severidad por defecto | Se reporta en |
| --- | --- |
| Warning | Spec (proyectos de implementación) |

## Qué significa

El enunciado de un requisito activo ya no coincide con la versión registrada en `spectrace.lock`, y este proyecto
tiene código con `[Implements]` para él. Ese código se escribió contra el texto anterior y puede no cumplir el nuevo.

Solo cuenta el enunciado: los cambios de título, de estado, de espacios o de saltos de línea no disparan la regla.
Los cambios en los criterios de aceptación los avisa ST0011 en los proyectos de test.

## Ejemplo

```text
## ORD-002: Cancelar pedido
While an order is in state Pending, when the customer cancels it,
the system shall move it to state Cancelled and refund the payment.   ← se añadió "and refund the payment"
```

```text
warning ST0010: El enunciado de 'ORD-002' cambió después de la última revisión (spectrace.lock).
Revisa OrderService.Cancel(Order) y, cuando esté al día, ejecuta: dotnet spectrace lock --requirement ORD-002
```

## Cómo arreglarlo

1. Revisa el código indicado contra el enunciado nuevo (`git diff` de la spec muestra qué cambió) y adáptalo.
2. Revisa si los criterios siguen describiendo el comportamiento; si no, actualízalos.
3. Registra la revisión: `dotnet spectrace lock --requirement ORD-002`, y haz commit de `spectrace.lock` junto al cambio.

Registrar la revisión es una decisión humana, como aprobar una PR. La skill y el servidor MCP piden a los agentes que
no la ejecuten por su cuenta.

## Configurar la severidad

En un `.globalconfig` en la raíz del repositorio (no `.editorconfig`: la regla se reporta sobre ficheros `.md`):

```ini
is_global = true
dotnet_diagnostic.ST0010.severity = error   # o warning, suggestion, none
```
