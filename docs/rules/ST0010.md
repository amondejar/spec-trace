# ST0010: Statement changed after review

| Default severity | Reported on |
| --- | --- |
| Warning | Spec (implementation projects) |

## What it means

The statement of an active requirement no longer matches the version recorded in `spectrace.lock`, and this project
has code with `[Implements]` for it. That code was written against the previous text and may not satisfy the new one.

Only the statement counts: changes to the title, the status, whitespace or line breaks do not trigger the rule.
Changes to acceptance criteria are reported by ST0011 in the test projects.

## Example

```text
## ORD-002: Cancel order
While an order is in state Pending, when the customer cancels it,
the system shall move it to state Cancelled and refund the payment.   <- "and refund the payment" was added
```

```text
warning ST0010: The statement of 'ORD-002' changed after the last review (spectrace.lock).
Review OrderService.Cancel(Order) and, once it is up to date, run: dotnet spectrace lock --requirement ORD-002
```

## How to fix it

1. Review the listed code against the new statement (`git diff` on the spec shows what changed) and update it.
2. Check whether the criteria still describe the behavior; update them if not.
3. Record the review: `dotnet spectrace lock --requirement ORD-002`, and commit `spectrace.lock` with the change.

Recording the review is a human decision, like approving a pull request. The skill and the MCP server ask agents not to
run it on their own.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: the rule is reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0010.severity = error   # or warning, suggestion, none
```
