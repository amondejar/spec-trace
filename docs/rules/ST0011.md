# ST0011: El criterio cambió después de revisarse

| Severidad por defecto | Se reporta en |
| --- | --- |
| Warning | Spec, en la línea del criterio (proyectos de test) |

## Qué significa

El texto de un criterio de aceptación ya no coincide con la versión registrada en `spectrace.lock`, y este proyecto
tiene tests con `[Verifies]` para ese criterio. El test puede seguir en verde aunque ya no compruebe lo que dice la spec.

Un criterio **nuevo** (sin huella en el lock) no dispara esta regla: si no tiene test, lo avisa ST0005.

## Ejemplo

```text
- AC-2: Given an empty cart, when it is submitted, then the request is rejected with an error.   ← se añadió "with an error"
```

```text
warning ST0011: El criterio AC-2 de 'ORD-001' cambió después de la última revisión (spectrace.lock).
Revisa OrderServiceTests.Create_with_empty_cart_is_rejected() y, cuando esté al día, ejecuta:
dotnet spectrace lock --requirement ORD-001
```

## Cómo arreglarlo

1. Revisa los tests indicados: ¿comprueban el texto nuevo? En el ejemplo, que además se devuelva un error.
2. Si el código tampoco lo cumple, cámbialo.
3. Registra la revisión: `dotnet spectrace lock --requirement ORD-001`.

## Configurar la severidad

En un `.globalconfig` en la raíz del repositorio (no `.editorconfig`: la regla se reporta sobre ficheros `.md`):

```ini
is_global = true
dotnet_diagnostic.ST0011.severity = error   # o warning, suggestion, none
```
