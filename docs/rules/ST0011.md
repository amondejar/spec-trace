# ST0011: Criterion changed after review

| Default severity | Reported on |
| --- | --- |
| Warning | Spec, on the criterion line (test projects) |

## What it means

The text of an acceptance criterion no longer matches the version recorded in `spectrace.lock`, and this project has
tests with `[Verifies]` for that criterion. The test may still pass even though it no longer checks what the spec says.

A **new** criterion (with no fingerprint in the lock file) does not trigger this rule: if it has no test, ST0005 reports it.

## Example

```text
- AC-2: Given an empty cart, when it is submitted, then the request is rejected with an error.   <- "with an error" was added
```

```text
warning ST0011: Criterion AC-2 of 'ORD-001' changed after the last review (spectrace.lock).
Review OrderServiceTests.Create_with_empty_cart_is_rejected() and, once it is up to date, run:
dotnet spectrace lock --requirement ORD-001
```

## How to fix it

1. Review the listed tests: do they check the new text? In the example, that an error is also returned.
2. If the code does not satisfy it either, change it.
3. Record the review: `dotnet spectrace lock --requirement ORD-001`.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: the rule is reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0011.severity = error   # or warning, suggestion, none
```
