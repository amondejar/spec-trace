# ST0012: Statement is not a requirement

| Default severity | Reported on |
| --- | --- |
| Info | Spec |

## What it means

The statement does not say what the system **shall** do. A requirement written as a wish ("Users can search
rooms", "The search should be quick") does not say who triggers it, when, or what the system must answer, so two people
build two different things.

EARS (Easy Approach to Requirements Syntax) gives five patterns, all with *shall*:

| Pattern | Template |
| --- | --- |
| Event | **When** &lt;trigger&gt;, the system **shall** &lt;response&gt; |
| State | **While** &lt;state&gt;, the system **shall** &lt;response&gt; |
| Unwanted behaviour | **If** &lt;condition&gt;, **then** the system **shall** &lt;response&gt; |
| Optional feature | **Where** &lt;feature is included&gt;, the system **shall** &lt;response&gt; |
| Always | The system **shall** &lt;response&gt; |

*must* and the Spanish *deberá* / *debe* are accepted as the same intent.

## Example

```text
The search should be quick.                                                  <- ST0012
When a client searches by name, the system shall return the rooms whose name contains the text.
```

## How to fix it

Rewrite the statement with one of the patterns. If you cannot say the trigger or the response, the requirement
is not ready to be approved.

For contradictions between the statement and the criteria, or missing cases, ask an agent with the `review_spec` MCP
prompt before approving the requirement.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: several rules are reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0012.severity = info   # or error, warning, suggestion, none
```
