# ST0013: Vague term in a requirement

| Default severity | Reported on |
| --- | --- |
| Warning | Spec |

## What it means

A word in the statement or in a criterion hides a number, a limit or a decision that nobody has made: *fast*,
*easy*, *user-friendly*, *appropriate*, *several*, *etc.*, *and/or*, *if possible*, *TBD*... (and their Spanish
equivalents: *rápido*, *fácil*, *adecuado*, *varios*, *y/o*, *si es posible*...). Whoever implements it chooses the
meaning, and the test cannot fail.

## Example

```text
- AC-1: Given 1000 rooms, when searching, then results appear quickly.        <- ST0013 'quickly'
- AC-1: Given 1000 rooms, when searching, then the results arrive within 300 ms.
```

## How to fix it

Replace the word with what it means: a number, a limit, a list, a condition. If nobody knows yet, it is an open
question for the person who approves the requirement, not something to guess in the code.

For contradictions between the statement and the criteria, or missing cases, ask an agent with the `review_spec` MCP
prompt before approving the requirement.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: several rules are reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0013.severity = warning   # or error, warning, suggestion, none
```
