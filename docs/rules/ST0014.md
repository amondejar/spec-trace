# ST0014: Acceptance criterion without an outcome

| Default severity | Reported on |
| --- | --- |
| Info | Spec |

## What it means

An acceptance criterion does not say what is observed when it is met: there is no *then* (or *entonces*). A
criterion like "The search works with filters" cannot be turned into a single test with a clear pass or fail.

## Example

```text
- AC-2: The search works with filters.                                         <- ST0014
- AC-2: Given rooms with 4 and 8 seats, when searching with minCapacity 8, then only the 8-seat room is returned.
```

## How to fix it

Write it as *Given* &lt;context&gt;, *when* &lt;action&gt;, *then* &lt;expected result&gt;, one behaviour per criterion.

For contradictions between the statement and the criteria, or missing cases, ask an agent with the `review_spec` MCP
prompt before approving the requirement.

## Configure the severity

In a `.globalconfig` at the repository root (not `.editorconfig`: several rules are reported on `.md` files):

```ini
is_global = true
dotnet_diagnostic.ST0014.severity = info   # or error, warning, suggestion, none
```
