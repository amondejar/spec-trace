# ST0015: Architecture rule broken

| Default severity | Reported on |
| --- | --- |
| Warning | Code |

## What it means

An approved architecture rule (`## ARC-n` in a spec with `kind: architecture`) says that code in some namespaces must
not use some namespaces, types or members, and this code does: a `using`, a type, a constructor, a property or a
method call. Typical cases: the domain using ASP.NET Core, the domain reading the clock directly instead of an injected
`TimeProvider`, endpoints reaching the storage without going through the domain services.

## Example

```markdown
## ARC-002: Time is injected
In: RoomBooking.Domain
Must not use: System.DateTime.Now, System.DateTime.UtcNow
Use instead: TimeProvider
```

```csharp
namespace RoomBooking.Domain;

public sealed class BookingService
{
    private DateTime Now => DateTime.Now;   // ST0015: ARC-002 (Time is injected): code in RoomBooking.Domain must not
                                            // use System.DateTime.Now. Use instead: TimeProvider
}
```

## How a rule is written

- `In:` the namespaces the rule applies to, comma-separated; namespaces below them are included
  (`RoomBooking.Domain` covers `RoomBooking.Domain.Rooms`, not `RoomBooking.DomainEvents`).
- `Must not use:` full names, comma-separated: a namespace (everything in it), a type (and its members) or a member
  (`System.DateTime.Now`). `Must not depend on:` is the same.
- `Use instead:` optional, shown in the message.
- `Status:` `approved` (the default) is checked; `proposed` and `draft` rules are only shown to people and agents.
- Any other text is the rationale. Text outside the rules is the project's principles, which agents receive with
  `get_architecture` and with `get_requirement`.

## How to fix it

Move the code to the layer the rule expects, or use the alternative it names. If the rule is wrong for this case,
change the rule in the spec (a person decides, in a reviewed pull request), not the code around it.

## Configure the severity

In a `.globalconfig` at the repository root:

```ini
is_global = true
dotnet_diagnostic.ST0015.severity = error   # or warning, suggestion, none
```

With `-warnaserror:ST0015` in CI, a pull request that breaks an approved rule does not pass.
